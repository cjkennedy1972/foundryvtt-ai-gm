## Blocking issue

The live macOS startup test still fails before Foundry authentication. Chrome starts or attempts to start, but the DevTools connection closes before a usable tab is created:

```text
could not dial ws://127.0.0.1:<dynamic-port>/devtools/browser/<id>: EOF
```

Other observed variants are:

```text
create browser context: context canceled
create isolated tab: start browser: context canceled
login form not found: context deadline exceeded
```

Because no browser tab survives, the relay never reaches Foundry administrator authentication, world selection, module connection, or AI-GM WebSocket registration.

## Current conclusion

The credential and Foundry workflow logic are implemented, but the application is not end-to-end operational on this macOS environment because the relay-launched Chrome DevTools session terminates before browser navigation. The next model should focus narrowly on Chrome process/CDP startup rather than changing Foundry credentials or campaign logic.
